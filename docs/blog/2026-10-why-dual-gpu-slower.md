# 为什么你的双卡只跑出单卡速度

> 一句话结论：**在 MoE 本地推理里，第二张卡插在哪个槽，比第二张卡本身重要得多。**
> 一张 4070S 插进芯片组的 x4 槽，会让整机比只装一张 3080 还慢 30%。

## 一个反直觉的实测

我用 Strata 的实测锚点标定了一个时间模型，然后跑了四个配置（UD-Q4 权重，256K 上下文，单路）：

| 配置 | PCIe 实际链路 | 专家命中 | 解码（物理口径） |
|---|---|---|---|
| 单张 3080-20G | x16 / 31.5 GB/s | 79.7% | **48.0 t/s** |
| 3080-20G + 4070S | x16 **+ 芯片组 x4 / 7.9 GB/s** | 84.2% | **33.6 t/s** |
| 双 3090 | x8 / x8，各 31.5 GB/s | 92.1% | **73.0 t/s** |
| 双 3080-20G | x8 / x8，各 31.5 GB/s | 88.1% | **61.8 t/s** |

第二行是重点：**多了 12G 显存、命中率还涨了 4.5 个百分点，解码却掉了 30%。**

## 为什么会这样

MoE 的专家权重分三级驻留：显存 → 内存 → NVMe。解码时每个 token 都要按路由把对应专家取到计算单元上。当模型被 layer-split 切到两张卡上：

1. 每张卡只持有自己那几层的专家；
2. 卡与卡之间必须交换激活值和 KV；
3. 这一步的带宽就是 **PCIe 实际协商速率**，不是显卡标称的显存带宽。

而 PCIe 的「x4 芯片组」和「x16 CPU 直连」差多少？看数字：

```
CPU 直连 x16 Gen4 = 31.5 GB/s    → frac 1.00
芯片组    x4 Gen4 =  7.9 GB/s    → frac 0.25
```

这就是 `pcie_frac`。它不进显存、不进算力，只在时间模型里做一件事：**把走这条链路的那部分专家访问变慢 4 倍**。

时间模型长这样（`src/sim.js`）：

```
t = f_V / (K1 · hw)        ← 显存驻留：算力决定
  + f_R / (K2 · pcieEff)   ← 内存驻留：走 PCIe
  + f_D / (K2 · 0.01)      ← 盘驻留：灾难
decode = think / max(t, T_FLOOR) × 1.5
```

`pcieEff` 是所有卡 `frac` 的平均值。一张 1.00 加一张 0.25，平均值被拉到 0.625 —— 于是**两张卡的机器，带宽等效于 0.625 张**。

## 那为什么双 3090 就快

因为 x8/x8 拆分后每张卡还是 31.5 GB/s（Gen4 x8 跑满约 25 GB/s，等效 `frac` 仍接近 1）。链路不拖后腿，多出来的显存和 SM 才是净收益：

```
单卡 48.0 → 双卡 73.0   (+52%)
```

同样是"两张卡"，差距来自**槽位**，不是显卡。

## 三个可以直接拿走的选择

1. **先看主板手册的拆分表**。PCIe 槽的物理长度会骗人：x16 长的槽可能只走 x4，而且挂在芯片组上。
2. **第二张卡优先插 CPU 直连槽**，哪怕要降到 x8/x8。x8/x8 ≈ 25 GB/s，远好于芯片组 x4 的 7.9。
3. **算力过剩时，别急着加卡**。命中率从 80% 到 85% 的收益，可能被链路拖累完全吃掉。

## 自己验证

这个结论不是嘴上说的，你可以改参数自己复现：

- 在线：<https://piccatapro.github.io/strata-pc-simulator/>
- 本地：`npm run serve` → `http://127.0.0.1:8080/src/index.html`

把第二张卡从「芯片组槽」拖到「CPU 直连槽」，仪表盘上的 decode 会立刻变。注意看主板上 PCIe 槽的**颜色**：绿 = 满速，橙 = 半速，红 = 芯片组。

**口径说明**：以上是模拟器基于 Strata 实测锚点（两台真机 + 官方社区 bench）标定的相对估算，绝对值有 ±20% 误差，不代表任何具体硬件组合的绝对性能。它回答的是「哪个选择更好」，不是「我的机器能跑多少」。
